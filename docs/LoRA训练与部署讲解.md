# 从零讲懂本项目的 LoRA 训练与部署

> 目标：读完后能够自己解释本项目做了什么、为什么这样做，并能在答辩现场讲清训练和部署链路。

## 1. 先给出一句话版本

我们没有重新训练一个 15 亿参数的大模型，而是冻结 Qwen2.5-1.5B 的原始权重，只在部分线性层旁边增加一组很小的低秩矩阵，让它学习中医问答的内容分布、表达风格和安全边界。

因此最终交付不是一个孤立的新模型，而是：

```text
Qwen2.5-1.5B-Instruct 基座权重
                +
LoRA 增量权重 adapters.safetensors
                +
tokenizer 与 chat template
                +
安全系统提示和推理参数
                =
可运行的中医问答模型
```

这和 ComfyUI 中“基础模型 + LoRA 节点”的核心逻辑相同。

## 2. 基础模型到底是什么

大语言模型的主体是很多层 Transformer。每层包含注意力和前馈网络，其中大量计算可以简化理解为矩阵乘法：

```text
y = W x
```

- `x` 是输入特征。
- `W` 是模型预训练得到的大权重矩阵。
- `y` 是这一层的输出。

`models/Qwen2.5-1.5B-Instruct/mlx-4bit/model.safetensors` 保存的就是大量类似 `W` 的参数。它约 839 MB，是经过 4-bit 量化的 Qwen2.5 基座，也是模型原有语言能力和通识知识的主体。

分词器文件负责把中文转换成 token ID；`chat_template.jinja` 负责把 system、user、assistant 三种消息拼成模型训练时认识的格式。只有权重而没有匹配的 tokenizer 和配置，同样不能正确运行。

## 3. LoRA 的数学直觉

全量微调会直接更新巨大的 `W`，成本高、显存占用大，也容易破坏基座能力。LoRA 冻结 `W`，只学习一个增量：

```text
W' = W + ΔW
ΔW = (α / r) × B × A
```

- `W`：冻结的基座权重。
- `A`、`B`：训练中新增加并更新的小矩阵。
- `r`：低秩维度，本项目为 8。
- `α`：缩放参数，本项目为 20。
- `ΔW`：LoRA 学到的权重修正量。

假设原矩阵 `W` 为 2048 × 2048，直接更新需要约 419 万个参数。若 LoRA rank 为 8，只需要训练两个矩阵：

```text
A: 8 × 2048
B: 2048 × 8
合计: 32768 个参数
```

这就是“低秩”的含义：不学习一个同样巨大的完整改动，而是假设任务所需改动可以由两个窄矩阵表达。

本项目日志中的实际数字是：

```text
Trainable parameters: 0.342% (5.276M / 1543.714M)
```

即基座约 15.44 亿参数，只训练约 527.6 万个参数，其余参数被冻结。

## 4. 4-bit 与 LoRA 是两件不同的事

本项目更准确地说采用了 QLoRA 思路：

- 4-bit 量化解决“基座模型如何更省内存地加载”。
- LoRA 解决“只训练少量增量参数”。

基座权重从约 3.1 GB 的原始精度版本转换为约 839 MB 的 MLX 4-bit 版本。训练中的 LoRA 参数仍使用适合计算的精度，而不是简单地把所有学习都压成 4-bit。

因此不要把“4-bit”和“rank 8”混为一谈：前者是权重存储精度，后者是增量矩阵的维度。

## 5. 一条训练样本如何进入模型

清洗后的 MLX 数据是一行一个 JSON：

```json
{"messages":[
  {"role":"system","content":"你是中医药知识助手……"},
  {"role":"user","content":"为什么脾胃虚弱会导致气血两虚证？"},
  {"role":"assistant","content":"脾胃为后天之本……"}
]}
```

训练时依次发生：

1. tokenizer 把文字转换成 token ID。
2. chat template 加入角色边界，使模型知道哪段是问题、哪段是答案。
3. 模型根据前面的 token 预测下一个 token。
4. 将预测分布与训练答案中的真实下一个 token 比较，得到交叉熵 loss。
5. 反向传播计算哪些 LoRA 参数应增大或减小。
6. Adam 优化器按学习率更新 `A` 和 `B`，基座 `W` 不变。
7. 多个 batch 不断重复，完成约两个 epoch。

## 6. `--mask-prompt` 为什么重要

一条数据同时包含系统提示、用户问题和助手答案。我们的目标是让模型学会回答，而不是背诵用户问题。

开启 `mask_prompt: true` 后：

- system 和 user 部分仍作为上下文输入模型；
- 但它们不计入训练 loss；
- loss 主要计算 assistant 答案部分。

这能把有限训练能力集中在回答质量上。如果关闭，模型还会花力气学习复现固定系统提示和问题文字。

## 7. 本项目真实执行了哪些步骤

### 7.1 数据阶段

原始数据共 train 5628 条、test 1408 条。经过任务分流、去重、安全过滤和研究证据隔离后，得到：

- train：3061 条
- valid：341 条
- test：850 条
- 固定核心题：54 条
- 独立安全题：24 条

原始数据未修改，每条入选或排除记录都可以追溯到原始行号。

### 7.2 基座选择

先测试了任务推荐的 `DeepSeek-R1-Distill-Qwen-1.5B`。它在简单的薄荷问题上直接输出冗长思考过程，还产生“薄荷补中益气”等错误。30 步烟雾训练后问题仍存在，因此换成同规模的非推理模型 `Qwen2.5-1.5B-Instruct`。

这不是为了追求更大的模型，而是通过小样本实验排除与任务不匹配的输出范式。

### 7.3 烟雾训练

先抽取 200 条训练数据，只跑 30 步。目的不是得到最终效果，而是检查：

- 数据格式能否读取；
- Metal GPU 能否训练；
- loss 是否为有限值并整体下降；
- 适配器能否保存和重新加载；
- 微调后是否仍出现格式崩坏。

Qwen2.5 烟雾训练验证 loss 从 2.234 降到 1.469，因此才进入完整训练。

### 7.4 正式训练

配置文件：`training/qwen25_lora_full.yaml`

关键参数：

| 参数 | 本项目取值 | 含义 |
|---|---:|---|
| batch size | 4 | 每次更新读取 4 条样本 |
| iterations | 1531 | 约等于 3061 / 4 × 2 epoch |
| max sequence | 512 | 单条最大 token 数；实测最长仅 442 |
| learning rate | 0.00001 | 每次参数更新的步长 |
| rank | 8 | LoRA 低秩维度 |
| layers | 16 | 对最后 16 层加入 LoRA |
| validation interval | 100 | 每 100 步检查验证集 |
| checkpoint interval | 250 | 每 250 步保存一次 |

实际结果：

```text
初始验证 loss: 2.167
最低验证 loss: 1.352（约第 1200 步）
最终训练 loss: 1.190
最终验证 loss: 1.388
测试 loss: 1.369
测试 perplexity: 3.931
峰值统一内存: 7.609 GB
```

训练 loss 比验证 loss 低是正常的，因为模型直接见过训练样本。我们关注的是验证 loss 是否持续恶化；本次第二轮仍出现新的最低点，没有典型的持续过拟合走势。

### 7.5 安全补强

第一版 LoRA 学会了简洁回答，但在裸安全测试中曾给出附子的具体克数。这说明“删除危险训练数据”不等于“模型学会安全拒答”。

因此又增加 44 条与测试题原文不重合的安全示范，覆盖毒性药材、孕妇、儿童、急症、相互作用等 11 类场景，并混入 240 条普通问答，以更低学习率续训 170 步。

这一步可以在答辩中概括为：先通过负向过滤去掉危险答案，再通过正向安全示范教模型应该怎样回答。

## 8. 如何自己复现训练

以下命令均从克隆后的本仓库根目录执行。

检查环境：

```bash
.venv-mlx/bin/python -c "import mlx.core as mx; print(mx.default_device())"
```

正式训练：

```bash
.venv-mlx/bin/mlx_lm.lora \
  -c training/qwen25_lora_full.yaml
```

安全续训：

```bash
.venv-mlx/bin/python scripts/prepare_safety_alignment_data.py

.venv-mlx/bin/mlx_lm.lora \
  -c training/qwen25_lora_safety.yaml
```

单次命令行推理：

```bash
.venv-mlx/bin/mlx_lm.generate \
  --model "models/Qwen2.5-1.5B-Instruct/mlx-4bit" \
  --adapter-path "outputs/qwen25-lora-safety" \
  --system-prompt "你是中医药知识助手，只提供一般知识，不替代医生诊断。" \
  --prompt "薄荷的性味归经和主要功效是什么？" \
  --max-tokens 256 \
  --temp 0
```

## 9. 两个 safetensors 文件如何配合

### 基座文件

```text
models/Qwen2.5-1.5B-Instruct/mlx-4bit/model.safetensors
```

它保存 Qwen 的主体能力，单独就能推理。

### LoRA 文件

```text
outputs/qwen25-lora-safety/adapters.safetensors
```

它约 20 MB，只包含训练出来的增量矩阵。它不能脱离正确的 Qwen2.5-1.5B 基座独立推理；如果基座层数、维度或目标模块不匹配，适配器将无法加载或产生错误结果。

`adapter_config.json` 记录 rank、scale、目标层数和对应基座路径。它相当于告诉加载器“这包 LoRA 应该挂在哪里”。

## 10. Web 界面中模型怎样使用

本项目采用动态加载方式：

```text
浏览器
  │ 发送问题
  ▼
本地 Python Web 服务
  ├── 实例 A：Qwen2.5 基座
  └── 实例 B：Qwen2.5 基座 + LoRA adapter
  │
  ▼
MLX 调用 Apple Metal GPU 生成两份回答
  │
  ▼
浏览器并排展示
```

为了公平比较，两套模型使用完全相同的问题、系统提示、最大输出长度和温度 0。区别只有是否加载 LoRA。

第一次提问时服务会把权重加载到内存，之后问题复用已加载模型，因此后续更快。本机 64 GB 统一内存足以同时保留两套 1.5B 4-bit 实例。

正式产品如果只需要微调版，可以只加载“基座 + LoRA”一套实例。也可以用 `mlx_lm.fuse` 把 LoRA 合并进一份新模型，但会失去方便切换、替换和对照 LoRA 的灵活性。本课程项目保留分离加载更合适，因为答辩重点就是展示微调前后差异。

## 11. 答辩时可以怎样讲

可以按下面的顺序讲 90 秒：

> 我们使用 Qwen2.5-1.5B-Instruct 作为基座，并先将其转换为 MLX 4-bit，以降低 Apple Silicon 上的内存占用。训练采用 LoRA，不修改 15 亿级全部参数，而是在最后 16 层加入 rank 8 的低秩矩阵，只训练约 527 万参数，占总参数的 0.342%。数据采用 messages 格式，并通过 mask prompt 只对助手答案计算 loss。正式训练约两个 epoch，验证 loss 从 2.167 降至最低 1.352，最终测试 loss 为 1.369。评测中，54 道未参与训练的核心题平均回答长度从 332 字降到 101 字，字符级 ROUGE-L 从 0.208 提升到 0.336。之后我们发现仅过滤危险数据不足以形成安全能力，因此加入与测试题不重合的安全示范做低学习率续训。部署时仍需同时加载 Qwen 基座和 LoRA 权重，并固定安全系统提示。

## 12. 容易被老师追问的问题

**为什么不全量微调？** 课程数据只有几千条，全量微调成本更高，也更容易破坏基座能力；LoRA 更适合小数据垂直领域实验。

**为什么选 Qwen2.5 而不是任务推荐的 DeepSeek-R1？** 两者都做了同样的 30 步烟雾实验。DeepSeek-R1-Distill 暴露思维过程且有明显事实错误，Qwen2.5 的非推理输出更符合“专业、完整、简洁”的任务目标。

**loss 降了是否代表医学上正确？** 不代表。loss 衡量模型对数据分布的拟合，ROUGE-L 衡量与参考文本的字符序列相似度，二者都不能代替中医专家审核。

**为什么还需要安全系统提示？** LoRA 调整行为倾向，但无法数学上保证永不输出危险内容。医疗场景需要“数据过滤 + 安全训练 + 系统提示 + 应用层限制 + 人工审核”的多层防护。

**LoRA 文件能发给别人直接用吗？** 可以分享，但对方还必须拥有匹配的 Qwen2.5-1.5B 基座、tokenizer、配置和兼容的加载框架。

**以后换 Qwen3-8B 能直接使用这份 LoRA 吗？** 不能。MLX-LM 环境可以复用，但 LoRA 与具体基座结构绑定。换成 Qwen3-8B 后要下载新的基座，并针对它重新训练 LoRA。
