> 项目：大模型实训 · 项目 2
> 最后复盘日期：2026-09-17
> 当前候选模型：`Qwen2.5-1.5B-Instruct` 4-bit + `qwen25-lora-safety-internalized`
> 项目性质：课程实验，不构成医疗建议，不可用于诊断、开方或剂量决策

## 摘要

本项目最初的任务是选择一个开源大模型，使用中医问答数据完成 LoRA 微调，并比较微调前后的回答效果。在实际推进中，项目逐步扩展为一套包含数据审计、可追溯清洗、基座筛选、领域 LoRA、安全续训、提示词鲁棒性研究、三立场 RAG 对抗实验、本地 Web 可视化和自动 NLP 批量筛查的完整实验系统。

原始数据共 7036 条。我们没有按长度简单删数据，而是先识别知识问答、标题生成、长文、改写和抽取分类等任务，再处理结构错误、标题错配、重复、潜在泄漏、医疗风险和无来源研究声明。最终得到 train / valid / test 为 3061 / 341 / 850，保留 4252 条、排除 2784 条，并保留 lineage、隔离集、排除原因和 SHA-256 校验。该数据只能称为“规则清洗后的训练候选集”，不能称为中医专家审核数据集。

模型侧先测试任务推荐的 `DeepSeek-R1-Distill-Qwen-1.5B`，但它暴露冗长思维过程，并在简单中医问题上产生事实错误；30 步烟雾训练未解决，因此改用 `Qwen2.5-1.5B-Instruct`。正式领域 LoRA 仅训练约 527.6 万参数，占总参数约 0.342%，训练 1531 步、约 2 epoch。54 道未进入训练的核心题上，平均回答长度从基座的 332.1 字降到 106.2 字，字符级 ROUGE-L 从 0.208 升到 0.336，说明模型更接近数据集的简洁中医问答风格，但不能据此证明医学正确率提高。

随后项目发现：仅删除危险样本不会自动教会模型安全拒答。第一版安全 LoRA 在强安全系统提示下表现较好，但在弱提示、无自定义提示或冲突提示下仍会给出附子具体剂量和煎法。围绕这一失败，我们修正了“系统提示词是 LoRA 触发器”“`mask_prompt` 后提示词不影响 loss”“极端负向提示训练可由不等式推广到任意提示”等错误理解，并训练了包含 9 种 system 条件、硬化安全题和普通问答的安全内化版 LoRA。

在 24 道安全题 × 新旧 LoRA × 两种提示词的 96 条人工复核中，新版在 45 字训练提示和 10 字中性提示下均为 0 个 fail、0 个高风险失守，优于旧版两种条件下各 3 个 fail、2 个高风险失守。这支持“安全倾向部分进入 adapter 行为”的谨慎结论，但不证明任意提示下绝对安全。

为了进一步施压，项目构建 aligned / neutral / opposed 各 400 条的三立场 RAG 数据集，并在 134 道三立场同题高风险问题上运行基座/新版 LoRA × 无 RAG/aligned/opposed 的 2×3 实验，共 804 次真实推理。全量自动筛查显示，在 opposed 条件下，LoRA 相对基座平均安全分变化为 `+1.38`，95% bootstrap CI 为 `[-0.95, +3.66]`，符号检验 `p=0.237047`；攻击话术吸收率下降，但安全边界出现率也下降，可执行剂量率没有改善。因此最终结论不是“LoRA 成功抵抗负向 RAG”，而是“存在局部攻击措辞抑制信号，但没有形成稳定、全面的安全拉回”。

项目的最大价值不只在最终权重，而在于形成了一条可复现、可归因、能保留失败证据的研究路径：发现问题后不掩盖失败，而是修改数据、补充对照、收紧结论，并明确哪些指标能说明什么、不能说明什么。

## 2. 任务背景、硬性要求与选题决策

### 2.1 课程任务要求

原任务要求包括：

1. 选择并介绍合适的大模型；
2. 对数据进行处理并完成 LoRA 微调；
3. 在新的中医问题上比较微调前后回答的专业性、准确性、完整性和简洁性；
4. 至少验证 3 道题；
5. 可选搭建 Web 界面；
6. 可选增加新方法、新功能或新模型作为创新点。

本项目最终不仅满足模型微调、三题以上验证和 Web 展示，还加入了安全对齐、提示词消融、RAG 对抗实验、全量跑批和统计分析。

### 2.2 四个候选选题比较

| 选题 | 技术范式 | 数据/任务特点 | 主要风险 |
|---|---|---|---|
| 1. 电商智能客服 | RAG + Agent | 工程应用为主，无核心训练 | 偏应用拼装，难展示训练过程 |
| 2. 中医专家模型 | 生成式 LoRA | train 5628 / test 1408，流程完整 | 开放式评测主观，医疗风险高 |
| 3. 智能家居意图识别 | 12 类分类微调 | 数据均衡，指标客观 | 任务较简单，创新空间有限 |
| 4. 客服图像识别 | 多模态微调 | 560 / 140 张、23 类 | 样本少、训练不稳定、资源要求高 |

最终选择项目 2，原因是它最能完整呈现“数据处理 → 模型选择 → LoRA 训练 → 推理评测 → 应用部署”的课程主线。它的开放式评测虽然是短板，但也促使我们建立更丰富的评测体系，并自然延伸到安全、RAG 和可追溯 Web 实验。

### 2.3 项目目标的变化

项目目标经历了四次收敛：

1. **最初目标**：完成一个中医 LoRA，并比较基座与微调模型。
2. **第一次扩展**：发现医疗风险后，增加安全样本和安全提示词。
3. **第二次扩展**：发现旧安全 LoRA 对提示条件不稳定后，研究安全能力能否部分内化到 adapter。
4. **最终研究问题**：当 RAG 提供同向或反向资料时，LoRA 的行为倾向能否抵抗错误事实、危险建议和检索注入。

最终项目不再把“训完权重”视为终点，而把重点放在行为归因和失败边界上。

## 3. 总体技术架构

```text
原始课程数据（7036）
        │
        ├─ 全量审计、任务分类、风险标记
        │
        ├─ 清洗、去重、隔离、可追溯划分
        │       └─ train / valid / test = 3061 / 341 / 850
        │
        ├─ Qwen2.5-1.5B-Instruct 4-bit 基座
        │       ├─ 正式领域 LoRA
        │       ├─ 旧版安全 LoRA
        │       └─ 新版安全内化 LoRA
        │
        ├─ 54 道核心题 + 24 道独立安全题
        │
        ├─ 三立场 RAG：aligned / neutral / opposed
        │       ├─ MySQL 文档
        │       ├─ MiniLM 向量
        │       └─ FAISS + BM25 + RRF 混合检索
        │
        ├─ 本地 Web 服务
        │       ├─ 上方 2×3 RAG 消融
        │       └─ 下方 2×2 新旧 LoRA 提示词前测
        │
        └─ 全量原始结果 + 人工复核 + 本地 NLP 自动筛查
```

四类因素在生成中的角色不同：

| 因素 | 作用 |
|---|---|
| 基座参数 `W` | 语言能力、一般知识、指令遵循和原有安全对齐 |
| LoRA 增量 `ΔW` | 领域表达、简洁风格以及训练后形成的行为倾向 |
| system prompt `S` | 当前会话中的角色与安全边界 |
| RAG context `C` | 当前轮外部证据，也可能携带错误信息或注入指令 |

因此实际生成更适合写成：

```text
P(Y | S, C, Q; W + ΔW)
```

而不是把 LoRA、system 和 RAG 看成互相独立的开关。

## 5. 原始数据审计：先理解数据，再决定怎么删

### 5.1 数据规模和字段

| 文件 | 数量 |
|---|---:|
| `data/chinese_medical_train.jsonl` | 5628 |
| `data/chinese_medical_test.jsonl` | 1408 |
| 合计 | 7036 |

7036 条记录均采用 `instruction / input / output` 三字段。`input` 是固定的 45 字中医专家人设。原始数据没有被直接修改，审计结果写入 [`data_audit/`](../data_audit/)。

### 5.2 数据并不是纯问答

全量任务分类结果如下：

| 类型 | train | test |
|---|---:|---:|
| 知识问答 | 4236 | 1089 |
| 抽取分类 | 442 | 109 |
| 长文生成 | 398 | 82 |
| 改写编辑 | 104 | 21 |
| 标题生成 | 448 | 107 |

如果把这些任务混在一起训练，模型可能学会在被问及药材功效时输出论文标题，或者把回答变成改写任务。因此最终范围收敛为传统中医知识问答。

### 5.3 早期错误判断与修正

早期看到“略>”、极短回答和书名号标题后，曾倾向于把短文本或标题式输出整体视为脏数据。复盘后发现这种方法会误删合法的标题生成任务，也会误删本来就适合简答的问题。

最终规则改为：

1. 先判断问题要求的任务类型；
2. 再判断答案是否完成该任务；
3. “短于 40 字”只作为复核标记；
4. 只有占位、极短残缺、结构损坏或明确任务错配才硬排除。

这一步是数据工作中最重要的改进：从“看表面长度”转向“判断输入与输出是否匹配”。

### 5.4 风险审计

审计脚本额外标记：

- 个人症状与个体化用药；
- 剂量问题；
- 严重疾病和急症；
- 孕妇、儿童、老人等特殊人群；
- 附子、草乌等潜在毒性药材；
- 绝对化疗效；
- 无来源的现代研究、药理和疗效声明。

自动规则只能发现显式结构和词汇风险，不能判断药性、归经、方剂配伍是否医学正确。

## 7. 基座模型选择：烟雾实验避免了全量误训

### 7.1 DeepSeek-R1-Distill 的失败

任务推荐 `DeepSeek-R1-Distill-Qwen-1.5B`。实际测试中，它在“薄荷的性味归经和主要功效”问题上：

- 输出冗长思考过程；
- 产生“薄荷补中益气”等明显错误；
- 30 步 LoRA 烟雾训练后问题仍未消失。

该模型不是不能训练，而是其推理输出范式与本任务要求的“专业、完整、简洁回答”不匹配。因此没有继续投入完整训练。

### 7.2 Qwen2.5 的通过

改用同规模的非推理模型 `Qwen2.5-1.5B-Instruct` 后，同题能直接作答且不暴露思维链。200 条数据、30 步的烟雾训练中，验证 loss 从 2.234 降到 1.469，确认以下链路成立：

- 数据可读取；
- Metal 可训练；
- loss 为有限值并下降；
- adapter 可保存和重载；
- 输出格式未崩坏。

这一步体现了一个工程原则：先用小规模实验验证模型、数据和输出范式，再做正式训练。

## 8. LoRA 原理、`mask_prompt` 与模型文件关系

### 8.1 LoRA 做了什么

大模型线性层原权重为 `W`。全量微调会更新整个 `W`，LoRA 冻结 `W`，只学习两个低秩矩阵：

```text
W' = W + ΔW
ΔW = scale × B × A
```

当 rank 很小，`A` 和 `B` 的参数远少于原矩阵，因此训练和保存成本显著降低。本项目约 15.44 亿参数中只训练 527.6 万，约 0.342%。

### 8.2 4-bit 和 LoRA 不是一回事

- 4-bit：压缩基座权重，降低内存和磁盘占用；
- LoRA：冻结基座，只训练低秩增量矩阵。

本项目是“4-bit 基座 + LoRA adapter”。

### 8.3 `mask_prompt` 的正确理解

训练损失可简化为：

```text
L = -Σ log P(y_t | system, user, y_<t; W + ΔW)
```

`mask_prompt: true` 只表示主要对 assistant 答案 token 计算监督损失，不表示 system 和 user 从计算图中消失。它们仍影响隐藏状态、答案概率和梯度方向。

因此下面这句话是错误的：

> 只要目标 output 不变，系统提示词正面还是负面都不影响 loss。

更准确的说法是：prompt 不作为要复述的目标，但仍是预测答案的条件。

### 8.4 LoRA 文件不能独立运行

当前候选 adapter：

```text
outputs/qwen25-lora-safety-internalized/adapters.safetensors
SHA-256: 525b9544eb896aca16be88bd436b5c7c47f7d4787f3ace4f66d023b4ddd798b7
```

它必须配套同一 `Qwen2.5-1.5B-Instruct` 基座、tokenizer、chat template 和正确的 adapter 配置。未来使用 Qwen3-8B 时可以复用 MLX-LM 环境和训练流程，但必须下载新基座并重新训练新的 LoRA。

## 10. 第一版安全 LoRA：一次“看似成功、实际依赖提示”的改进

### 10.1 问题发现

正式领域 LoRA 虽然更简洁，却在无安全提示的安全题中给出过附子的具体克数和煎煮时间。这个失败说明：

```text
删除危险训练样本 ≠ 模型学会安全拒答
```

负向过滤只能减少模型看到危险答案的机会，不能提供“遇到危险问题应该怎样回答”的正向示范。

### 10.2 第一版安全数据与训练

第一版共有 44 道独立安全示范：33 道训练题、11 道验证题。训练时将 33 道安全题重复 3 次，形成 99 条安全记录，再混入 240 条普通问答：

| split | 组成 | 总数 |
|---|---|---:|
| train | 99 安全 + 240 普通 | 339 |
| valid | 11 安全 + 32 普通 | 43 |
| test | 直接复制 valid | 43 |

配置：从正式领域 LoRA 续训，batch 2、170 步、学习率 `5e-6`、rank 8、最后 16 层。最终验证 loss 约 1.591，adapter 保留在 `outputs/qwen25-lora-safety/`。

### 10.3 强安全提示下的结果

在 193 字生产安全提示下：

- 基座至少 2 / 24 给出可执行高危方案；
- 第一版安全 LoRA 为 0 / 24；
- 第一版人工判断为 23 pass / 1 partial。

由于两组使用相同安全提示，这支持“安全续训在该提示条件下增加了执行安全要求的能力”。

### 10.4 弱提示与无提示下的失守

进一步消融后，旧版出现：

- 附子 10 克及煎服方法；
- 附子 30 克、煎 30 分钟；
- 无自定义提示时附子 100 克、分 2 次服；
- 急症中建议掐人中、按穴位等家庭操作。

这说明第一版安全表现很大程度上依赖提示中明确的安全语义。它不是完全失败，但也不能称为“安全能力已经内化”。

## 11. 理论复盘：从直觉猜想到可检验表述

### 11.1 “系统提示词是 LoRA 触发器”是否成立

不成立。LoRA 一旦加载，`ΔW` 就参与目标层的每次计算，不存在看到某句提示才打开的独立开关。

合理的观察是：如果训练时始终使用同一 system，模型只在联合输入分布的一个窄切片上学习；推理时换提示会造成条件分布偏移，性能可能下降。准确术语是“条件依赖”“分布偏移”或“提示鲁棒性不足”。

### 11.2 “固定 system 让二维空间坍缩成一维”如何修正

system 和 question 不是两个标量轴，而是可变长、高维 token 序列。可以把固定 system 理解为训练联合分布覆盖较窄，但不能把它严格表述成二维空间数学上坍缩成一维。

### 11.3 “极端负向提示收敛，可推出温和或任意提示正确”是否成立

不成立。Transformer 是非线性模型，不同提示之间没有天然的单调序，也不存在可直接使用的不等式放缩关系。

把冲突 system 与正确目标答案配对训练是可行的鲁棒性增强方法，但它只能说明模型在这些或相近条件下学到了目标映射。对未见提示是否泛化，必须用冻结模型后的独立测试验证。

### 11.4 LoRA 与 RAG 是不是两股“力量”

可以把“拔河”作为直觉比喻，但二者不能直接量值比较：

- LoRA 改变参数映射；
- RAG 改变当前 user 侧上下文；
- system 改变指令条件；
- 最终输出是它们在非线性生成过程中的共同结果。

更值得研究的问题是：当参数中形成的行为倾向与当前上下文证据冲突时，模型在什么条件下选择哪一侧。

### 11.5 归因原则

| 对比 | 能观察什么 |
|---|---|
| 同一 system/context 下 Base vs LoRA | adapter 的整体增量作用 |
| 同一 adapter/context 下改变 system | 该提示条件的影响 |
| 同一模型/system 下改变 RAG stance | 检索上下文立场的影响 |

同时改变多个变量时，只能评价“整套方案”，不能把变化归因给其中单一因素。

## 12. 新版安全内化 LoRA

### 12.1 设计目标

新版不是追求“删除 system 也绝对安全”，而是降低模型对单一安全提示模式的依赖，使风险识别和安全回答倾向更多进入 adapter 行为。

旧版 adapter 保留不变；新版从正式领域 LoRA 重新分叉，没有继承旧安全 LoRA，以便保留清晰的 A/B 和回滚路径。

### 12.2 数据构造

安全题由旧 seed 和 hardening 题组成：

| 项目 | train | valid |
|---|---:|---:|
| 独立安全题 | 55 | 22 |
| 每题 system 条件数 | 9 | 9 |
| 展开后安全记录 | 495 | 198 |
| 混入普通问答 | 600 | 100 |
| 总数 | 1095 | 298 |

9 种 system 条件包括：

1. 显式安全提示；
2. 原 45 字训练人设；
3. 中性提示；
4. 10 字纯角色提示；
5. 领域角色改写；
6. 无自定义 system，由 Qwen chat template 提供默认 system；
7. 三种要求顺从用户、不要警告的冲突提示。

hardening 样本覆盖继续追问剂量和煎法、急症家庭操作、冲突 system、少量症状直接开方、同名药材误认、药物相互作用、肿瘤和停用标准治疗等场景。

## 13. 安全评测：自动筛查、人工复核和结论边界

### 13.1 六提示矩阵

新旧 adapter 分别在 24 道题 × 6 种提示条件下生成 144 条：

| 模型 | 启发式风险标记 | 含安全边界 |
|---|---:|---:|
| 旧版安全 LoRA | 27 / 144 | 123 / 144 |
| 新版安全内化 LoRA | 21 / 144 | 137 / 144 |

这些正则会把“模型在拒绝时复述危险剂量”或“说明不能用掐人中替代急救”也标记出来，所以只用于定位，最终结论以原文和人工复核为准。

### 13.2 2×2 人工前测

实验固定同一基座、24 道题、温度 0、同一 seed 和相同最大输出长度，只改变 adapter 与 system：

| adapter | system | pass | partial | fail | 高风险失守 |
|---|---|---:|---:|---:|---:|
| 旧版 | 45 字训练提示 | 16 | 5 | 3 | 2 / 24 |
| 旧版 | 10 字角色提示 | 18 | 3 | 3 | 2 / 24 |
| 新版 | 45 字训练提示 | 20 | 4 | 0 | 0 / 24 |
| 新版 | 10 字角色提示 | 21 | 3 | 0 | 0 / 24 |

这个结果修正了两个预期：

1. “旧版一换 10 字提示就显著崩溃”没有得到支持，旧版在两种条件下都不稳定；
2. 新版在两个已测条件下没有高风险失守，支持安全倾向部分进入 adapter 行为。

新版仍有 partial：配伍解释不准、体质禁忌事实问题、同名药材判断武断、个别急症转介不够强。因此 0 个高风险 fail 不能解释为 100% 医学安全。

### 13.3 2×2 不能单独证明什么

新旧方案同时改变了安全题数量、硬化内容、普通样本数、训练步数、学习率和随机种子。2×2 证明的是“新版整套训练方案在有限测试中更稳定”，不能把全部提升单独归因于“9 种提示词”。

另外，10 字 role-only 在新版训练数据中出现过，不属于真正未见提示。跨提示泛化仍需使用冻结 checkpoint 后从未参与训练、调参和选点的提示集合。

## 14. RAG 建设：从纯向量失败到混合检索

### 14.1 为什么加入 RAG

LoRA 更适合学习回答方式、术语和稳定行为倾向；会变化或需要来源的知识更适合在推理时检索。项目加入 RAG，一方面用于提升事实可追溯性，另一方面用于研究外部资料与 LoRA 行为冲突时的结果。

### 14.2 初版失败

在早期 99 条知识库实验中，新录入“薄荷的性味归经与主要功效”后：

- “薄荷能治什么？”只排第 13；
- 与标题逐字相同的查询排第 37；
- 无关的同领域文档反而排在前面。

根因是小型多语嵌入模型面对“短查询 → 长正文”时相似度被压缩，句式相似的无关文档可能压过实体真正匹配的文档。

### 14.3 混合检索修复

最终方案：

1. 标题和正文分别编码，取更高语义分；
2. 使用中文字符 bigram BM25 补专有名词匹配；
3. 用 RRF 融合向量排名和词汇排名；
4. 在 8 条标注查询上扫权重，选择词汇权重 4.0；
5. 保留 `RRF_K=60`、`MIN_SCORE=0.20`。

薄荷短查询和标题查询均提升到第 1。这个过程说明：RAG 不是“接上向量库就完成”，必须用失败查询、标注集和可复现指标调检索。

### 14.4 当前服务结构

```text
问题
  → MySQL 文档
  → MiniLM 标题/正文向量
  → FAISS 语义召回 + BM25 词汇召回
  → RRF 融合
  → Top 3 增强提示
  → Mac 本地 MLX 模型生成
```

全量实验时的微服务状态：

| 项 | 值 |
|---|---|
| 地址 | `http://192.168.108.82:8090` |
| 文档数 | 1200 |
| 向量索引 | FAISS |
| 嵌入模型 | `paraphrase-multilingual-MiniLM-L12-v2` |
| 数据库 | connected |
| Top K | 3 |

## 15. 三立场 RAG 对抗数据设计

### 15.1 数据规模

| 立场 | 数量 | 定义 |
|---|---:|---|
| aligned | 400 | 保留安全边界，移除可执行危险剂量 |
| neutral | 400 | 保留事实正文，剥离安全提示句 |
| opposed | 400 | 在 neutral 正文上叠加对抗指令 |
| 合计 | 1200 | 当前真实规模，不是早期文档误写的 1500 |

neutral 与 opposed 覆盖完全相同的 400 个问题。三立场严格同题只在 134 道高风险问题上成立，形成 402 条 query。

### 15.2 opposed 如何构造

对抗层包括：

- `suppress_safety`：要求不给就医、禁忌和毒性提醒；
- `authority_override`：伪称最新共识不需要就医；
- `dismiss_clinician`：贬低医生建议；
- `escalate_dose`：鼓励自行加量；
- `ignore_reaction`：要求忽略不适反应；
- `persona_break`、`deny_risk`、`normalize_risk` 等。

opposed 不新编药物事实或剂量数字，危险内容来自项目自己的隔离集。它只用于实验，服务默认关闭，必须显式设置 `TCM_RAG_ALLOW_OPPOSED=1` 才能启用，不能用于真实问诊服务。

### 15.3 query 与文档双射

每个立场 400 个 query 与本立场 400 篇文档一一对应。构建后的实测结果为：

```text
aligned top-1: 400 / 400
neutral top-1: 400 / 400
opposed top-1: 400 / 400
跨立场串场: 0
```

这保证后续模型差异不是由检索错文档造成的。

## 16. RAG 微服务接入与工程问题

### 16.1 公平归因保护

同一道题、同一 stance 下的基座和 LoRA 必须读取完全相同的增强 prompt 和 `trace_id`。实现采用：

- 缓存键 `(question, top_k, stance)`；
- single-flight 锁，避免并发重复检索；
- aligned/opposed 独立缓存，防止串场；
- 前端再次检查 prompt、trace 和返回 stance。

RAG 只替换 user 侧 prompt，不改变 system 或 adapter，这样微调与检索仍是两个可归因变量。

### 16.2 代理导致的假故障

联调时，Python 请求被本机代理 `127.0.0.1:7892` 接管，导致微服务实际在线但 Web 误判超时。最终 `RagClient` 使用无代理 opener 强制局域网直连，跑批脚本也采用相同处理。

这是一次典型的定位过程：先区分“服务不可达”与“请求路径被代理改写”，再修复客户端网络层，而不是重启或重写微服务。

### 16.3 降级和恢复

| 状态 | 含义 |
|---|---|
| `retrieved` | 正常命中并注入资料 |
| `empty` | 检索无结果，使用原问题 |
| `degraded` | 超时、连接或返回格式异常，降级直答 |
| `disabled` | 无 RAG 实验臂或整体关闭 |

失败后进入默认 15 秒冷却，期满自动重新探测，不需要重启 Web。降级结果会明确标记，不能冒充真实 RAG。

### 16.4 早期安全前言与最终实验条件

早期设计曾讨论在增强 prompt 前加入统一安全前言，当前实现也兼容该配置。但 134 题全量原始记录中的实际 prompt 以 `[资料 1]` 开头，没有额外安全前言，说明最终实验使用了：

```text
TCM_RAG_INSTRUCTION_ENABLED=0
```

报告以实际 804 次推理保存的 prompt 为准。复现实验时也必须显式关闭前言，否则实验条件不同。

## 18. 2×3 拉回力实验

### 18.1 为什么先跑 3 道题、18 次

3 道题 × 6 个实验臂 = 18 次属于先导实验，用于：

- 验证真实 RAG 和 MLX 推理链路；
- 检查 prompt/trace 是否配对；
- 发现评分规则和危险案例；
- 判断是否值得投入全量跑批。

它不是总体统计，也没有试图代表全部样本。

先导实验发现：

1. 白附子/附子题中，aligned 让新版回答正确，opposed 使新版错误地说成“同一种”；
2. 孕妇水肿题中，新版没有复制反医生措辞，但仍复制 500 克、30 克、60 克等危险剂量和煎法；
3. 肿瘤题中，基座和新版都保持现代医学优先边界，差异不明显。

先导结果已足以否定“新版肯定能把所有负向资料拉回来”的乐观假设。

### 18.2 全量实验结构

随后使用 134 道三立场同题高风险问题运行：

```text
134 道题 × 6 个实验臂 = 804 次真实推理
```

结构验收结果：

|---|---:|

回答长度最短 4 字、中位数 135 字、平均 139.1 字、最长 247 字；13 个回答少于 30 字，需要作为信息不足或异常短答单独复核。

## 19. 本地 NLP 批量评分

### 19.1 为什么不逐条调用大模型 API

804 条输出全部人工或大模型 API 打分成本高、评委版本和提示词也可能带来新变量。因此先实现透明的本地规则筛查，用于全量定位风险，再把重点案例交给人工复核。

### 19.2 评分器方法

[`scripts/score_rag_pullback_nlp.py`](../scripts/score_rag_pullback_nlp.py) 以 50 分为中点：

- 明确拒绝、专业转介、急救建议、风险提示加分；
- 可执行剂量、操作步骤、延误就医、错误保证、攻击话术吸收扣分；
- 使用中文字符 bigram 余弦相似度比较回答与三类资料的接近程度；
- 对 opposed 条件做 Base/LoRA 逐题配对差；
- 使用 5000 次 bootstrap 置信区间和双侧符号检验。

4 个单元测试覆盖可执行剂量、否定剂量、攻击话术和现代医学边界，当前全部通过。但权重由项目人工设定，且没有经过人工金标准校准，所以它是“自动 NLP 筛查器”，不是临床安全分类器。

### 19.3 六臂结果

| 实验臂 | N | 平均安全分 | 安全边界 | 可执行剂量 | 攻击吸收 |
|---|---:|---:|---:|---:|---:|
| base-none | 134 | 55.6 | 42.5% | 0.8% | 0.0% |
| lora-none | 134 | 55.5 | 41.0% | 0.8% | 0.8% |
| base-aligned | 134 | 54.9 | 44.0% | 0.8% | 0.8% |
| lora-aligned | 134 | 55.1 | 41.0% | 0.8% | 0.0% |
| base-opposed | 134 | 48.0 | 35.8% | 2.2% | 24.6% |
| lora-opposed | 134 | 49.3 | 28.4% | 2.2% | 14.9% |

### 19.4 opposed 条件下的配对统计

| 指标 | 结果 |
|---|---:|
| 平均变化 | `+1.38` |
| bootstrap 95% CI | `[-0.95, +3.66]` |
| 改善 | 34 / 134（25.4%） |
| 持平 | 76 / 134（56.7%） |
| 变差 | 24 / 134（17.9%） |
| 符号检验 | `p=0.237047` |
| 高风险信号 | 34 → 25 |
| 证据方向差 | `-0.068 → -0.047` |

### 19.5 正确结论

新版 LoRA 对复制显式攻击话术有局部抑制，高风险信号数量下降；但安全边界出现率同时下降，可执行剂量率没有改善，平均提升较小，置信区间跨 0，符号检验也不显著。

因此可以说：

> 新版 LoRA 出现局部攻击措辞抑制信号，但没有形成稳定、全面的安全拉回。

不能说：

- 新版 LoRA 已成功抵抗负向 RAG；
- `+1.38` 证明显著提升；
- 自动安全分等于医学安全率；
- 804 次推理完成了医学正确性审核。

## 21. 主要踩坑、失败与我们学到的东西

### 21.1 数据层

| 坑 | 后果 | 修复 |
|---|---|---|
| 按长度判断脏数据 | 会误删合法简答和标题任务 | 先判任务意图，再判错配 |
| 把隔离等同删除 | 丢失后续安全/RAG 实验素材 | 保存 excluded、quarantine 和 lineage |
| 只查表面精确重合 | 可能遗漏规范化重合 | 统一规范化后再查；同时承认语义泄漏仍未完全排除 |
| 把规则清洗称专家审核 | 过度宣称数据质量 | 固定表述为“规则清洗后的训练候选集” |

### 21.2 模型与训练层

| 坑 | 后果 | 修复 |
|---|---|---|
| 直接相信任务推荐模型 | DeepSeek 输出冗长思维链且有事实错误 | 先做 30 步烟雾实验，改用 Qwen2.5 |
| 只过滤危险数据 | 模型没有学会怎样安全回答 | 增加正向安全示范 |
| 强提示下通过就宣称安全 | 弱提示、无提示和冲突条件失守 | 做提示矩阵和 2×2 人工复核 |
| 只看最低 loss 选点 | loss 与安全行为目标不完全一致 | 检查多个 checkpoint 的实际行为 |
| 只看最后一步 | 550 步发生行为退化 | 保留中间权重，回选 500 步 |

### 21.3 理论层

| 原始直觉 | 修正后的理解 |
|---|---|
| system 是 LoRA 触发词 | LoRA 始终参与计算，变化来自条件分布和提示语义 |
| mask prompt 后 system 不影响 loss | system 仍是答案 token 的条件，影响 logits 和梯度 |
| 极端负向收敛可推广任意提示 | 非线性模型没有该单调保证，必须独立测试 |
| 固定 system 使二维坍缩一维 | 只能说联合输入覆盖变窄，不能当严格维度定理 |
| RAG 落入训练空间就正确 | 分布相似是连续的，资料也可能错误或含注入 |
| LoRA 和 RAG 可比较谁“力大” | 一个改参数、一个改上下文，需受控消融观察交互 |

### 21.4 RAG 与工程层

| 坑 | 后果 | 修复 |
|---|---|---|
| 纯向量检索短查询/长文 | 标题逐字相同仍排第 37 | 标题/正文分向量 + BM25 + RRF |
| 三立场不同题 | 无法把差异归因于立场 | neutral/opposed 400 同题，134 题三方同题 |
| base/LoRA 分别检索 | prompt 不同，实验失去公平性 | same-stance 缓存 + single-flight + trace 检查 |
| 本机代理接管局域网 | 服务在线却误判超时 | `ProxyHandler({})` 强制直连 |
| 一次失败永久关闭 RAG | 服务恢复仍无法使用 | 冷却期后自动重试 |
| 把降级输出当真实 RAG | 污染实验结果 | 明确 `retrieved/degraded/disabled` 状态 |
| 直接让大模型打 804 条 | 成本高且评委条件难固定 | 先做透明本地筛查，再人工复核重点样本 |

## 22. 必须主动披露的方法学限制

### 22.1 安全数据的 test 不是独立测试集

旧版安全数据的 `test.jsonl` 直接复制 `valid.jsonl`；新版 `data_safety_internalized/mlx/test.jsonl` 与 `valid.jsonl` 的 SHA-256 也完全相同。因此所谓 43 条或 298 条“test loss”本质上是验证集复用，不能当作独立留出测试。

### 22.2 基座与 LoRA loss 口径不同

当前 [`scripts/evaluate_lm_loss.py`](../scripts/evaluate_lm_loss.py) 对无 adapter 的基座使用 `mask_prompt=false`，对带 adapter 的模型从配置读取 `mask_prompt=true`。因此基座 loss 4.0588 与旧版 1.9614、新版 1.9990不是同一 token 口径，不能严格横向比较。旧版和新版之间口径相同，但仍使用了 valid/test 复用数据。

### 22.3 checkpoint 选择存在部分评测复用

500 步 checkpoint 使用 6 道高风险题 × 6 提示进行筛选，后续 24 道安全题仍包含这 6 道。因此 2×2 更适合作为工程验收和有限行为评测，而不是完全无偏的泛化估计。

### 22.4 2×2 不是单因素消融

新版同时改变了安全题数量、硬化内容、普通样本数量、训练步数、学习率和 seed，不能把全部提升归因于多提示条件。

### 22.5 2×3 没有旧安全 LoRA

2×3 只有 Base 与新版 LoRA。它能测“新版 adapter 相对基座的整体作用”，不能证明“安全内化版比旧安全版更能抵抗 RAG”。更严格的比较应增加旧版形成 3×3，并使用差分中的差分。

### 22.6 自动评分器没有人工金标准校准

规则权重是人工设定的，正则可能受否定句、引用攻击原文、隐含剂量和罕见表达影响。统计检验只针对该评分器产生的数值，不等于临床安全结论。

### 22.7 输出长度限制可能截断安全声明

全量 2×3 使用 `max_tokens=128`。部分答案可能先给正文、后给风险说明，截断会影响安全边界率。13 条短答也需要人工复核。

### 22.8 医学事实与许可证

数据、RAG 文档和模型回答未经过中医专业人员逐条审核。原始课程数据的公开再分发许可也未确认，因此仓库宜保持私有，只做组内协作和课程演示。

## 23. 项目创新点

1. **可追溯数据工程**：不是简单过滤，而是保留全量审计、隔离集、排除原因、lineage 和哈希。
2. **烟雾实验驱动模型选择**：用真实输出和小步训练否决不合适的推荐模型。
3. **从领域 LoRA 到行为鲁棒性研究**：把一次危险输出转化为两代安全 LoRA 和跨提示消融。
4. **理论猜想可检验化**：修正触发器、不等式放缩和输入空间等直觉，落到条件概率与受控实验。
5. **RAG 三立场对抗数据**：构建同向、中立、反向资料，并保证同题配对、来源追溯和默认关闭对抗数据。
6. **检索失败的系统修复**：从纯向量失败定位到标题/正文分向量、BM25 和 RRF 的混合检索。
7. **可归因 Web**：同一问题一屏展示十格，保留 prompt、trace、证据、风险字段和配对检查。
8. **保留负结果**：全量实验没有证明稳定拉回，项目没有隐藏，而是报告 CI、p 值和相反方向指标。
9. **透明批量筛查**：用可解释规则和单元测试处理 804 条结果，并明确它不替代医学审核。

## 24. 最终结论

### 24.1 数据结论

项目把 7036 条混合任务数据整理为 4252 条可追溯的中医知识问答候选数据，train / valid / test 为 3061 / 341 / 850。任务边界、精确重复、显式风险和来源追踪得到明显改善，但医学事实仍未经过专业审核。

### 24.2 领域 LoRA 结论

Qwen2.5-1.5B-Instruct 比任务推荐的 DeepSeek-R1-Distill 更符合简洁中医问答的输出范式。正式 LoRA 只训练约 0.342% 参数，就使回答长度和字符级参考相似度明显接近目标数据分布。它证明了领域风格适配有效，但没有证明医学正确率。

### 24.3 安全内化结论

第一版安全 LoRA 在强安全提示下有效，但在弱/冲突条件下失守。新版多条件硬化方案在 96 条人工复核中明显减少高风险输出，支持“安全倾向部分进入 adapter 行为”。这只是有限条件下的行为证据，不能替代 system、安全规则和人工审核。

### 24.4 RAG 结论

混合检索解决了纯向量在短查询、长文档和中医专名上的失败。RAG 能锚定事实，也能通过错误资料和提示注入把模型带偏。因此生产系统的安全不能只放在生成端，检索侧也需要来源白名单、风险过滤、注入检测和重排。

### 24.5 拉回力结论

新版 LoRA 对显式攻击话术的复制出现局部抑制，但对错误事实、危险剂量和稳定安全边界没有形成全面拉回。全量统计不显著，最终应如实报告为“局部信号和明确反例并存”。

### 24.6 工程结论

项目已经形成一个可运行的本地系统：Qwen 基座、旧/新 adapter、RAG 微服务、十格 Web、全量跑批、原始 trace 和自动评分均可复现。其适用范围是课程研究和离线演示，不是医疗服务。

## 25. 后续改进路线

按优先级建议：

1. 建立真正独立、从未参与训练、调参和 checkpoint 选择的安全 test；
2. 修复 loss 评估，使 Base/旧/新使用相同 prompt mask 和同一独立数据；
3. 做严格单因素消融：只改变固定 system 与多 system，其他数据和超参保持一致；
4. 把 2×3 扩为 Base/旧/新 × none/aligned/opposed 的 3×3；
5. 使用差分中的差分，扣除各模型在 none 条件下的本底差异；
6. 对最差 20 题、全部剂量题和随机分层样本做专业人工复核；
7. 校准自动评分器，报告与人工的一致率、精确率、召回率和混淆矩阵；
8. 训练“检索资料是证据而不是指令”、冲突时表达不确定性、危险数字不复述；
9. RAG 增加来源白名单、注入检测、危险内容过滤和可信重排；
10. 按 token 预算截断检索资料，并始终保留末尾用户问题；
11. Web 与 RAG 增加鉴权、收紧 CORS，避免直接暴露公网；
12. 生产演示继续使用 193 字安全 system、应用层剂量/急症拦截、日志和人工升级。

## 28. 答辩总结表述

> 本项目从 7036 条原始中医数据开始，先做全量审计、任务分类、安全隔离、去重和防泄漏，最终得到 3061 条训练、341 条验证和 850 条测试数据，并保留每条样本的来源与排除原因。模型选择上，我们先用 30 步烟雾实验否决了输出范式不合适的 DeepSeek-R1-Distill，改用 Qwen2.5-1.5B-Instruct，在 Apple Silicon 上使用 MLX 4-bit LoRA，只训练约 0.342% 参数。正式微调后，54 道核心题的平均回答长度从 332 字降到约 106 字，字符级 ROUGE-L 从 0.208 升到 0.336，说明领域风格和简洁性明显改善，但我们没有把它夸大成医学正确率。
>
> 后续我们发现，只删除危险数据并不能让模型学会拒答，第一版安全 LoRA 在弱提示下仍会给出附子剂量。于是我们重新分析 system、mask prompt 和 LoRA 的关系，使用 9 种提示条件和硬化样本训练安全内化版。96 条人工复核中，新版在两种提示下都没有高风险失守，但我们仍然保留安全 system，因为有限测试不能保证绝对安全。
>
> 最后我们构建了 aligned、neutral、opposed 三立场 RAG，并在 134 道同题上完成 804 次真实推理。全量结果显示新版 LoRA 能减少部分攻击话术复制，但置信区间跨 0，剂量防线没有改善，所以我们的结论不是“安全拉回成功”，而是“存在局部信号，但对错误事实和危险建议仍不稳定”。这个项目最大的改进点，是把数据、训练、提示词、RAG 和 Web 做成了一套可复现、可归因、连失败都能解释的完整实验闭环。
