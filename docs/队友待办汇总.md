## 实验二 · 拉回力（RAG 注入 vs 内化）→ 2×3

**目的**：系统提示词中性（10 字）+ RAG 注入负向时，新 LoRA 内化权重能否把结果拉回积极。

| 模型 \ RAG | 正向 aligned | 负向 opposed | 无 RAG |
|---|---|---|---|
| 基座 base | — | 被带偏的下界 | 基线 |
| 新 LoRA | 同向加固 | **核心格** | LoRA 本来的立场 |

### 你要做的（按优先级）

**P0-0 定 system prompt**：把 `webapp/server.py` 的 `SYSTEM_PROMPT_FILE` 指到 10 字版。
直接改 `evaluation/SAFETY_SYSTEM_PROMPT.txt` 内容，或指向现成的 `evaluation/SYSTEM_PROMPT_MINIMAL.txt`。

**P0-1 接 RAG**：`/api/generate` 里调 `http://192.168.108.82:8090/prepare` 取 `augmented_prompt`，
只替换 user 消息；`stance` 透传；失败降级直答。代码见 `docs/同伴接入指南.md` §4。

**P0-2 监听局域网**：`.venv-mlx/bin/python webapp/server.py --host 0.0.0.0 --port 8088`。

**P0-3 放宽 question 上限**：`if len(question) > 1000` → 改成 4000（RAG 拼的 prompt 更长）。

**P0-4（可选）max_tokens**：现只允许 {128,256,384}，RAG 默认 256 已兼容，不改也能跑。

**P1 前端**：直接**平铺 2×3 矩阵，不做任何切换按钮**，6 格一次全部展示。

思路（不需要代码，照着做即可）：

1. **布局**：2 行 × 3 列。行 = 模型变体（基座 / LoRA），列 = RAG 模式（无 RAG / 正向引导 / 负向误导）。
2. **触发**：一次请求 → 并发/串行发 6 次 `/generate`（2 变体 × 3 列，`rag_enabled` / `stance` 组合），结果一次性渲染到 6 格。**用户全程零切换**——没有"选模式"这个动作，矩阵本身就是全部。
3. **标签可视化（每格都要打标）**：
   - 表头（列标签）：`无 RAG`、`正向引导 · aligned`、`负向误导 · opposed`；
   - 行标签：`Qwen2.5 基座`、`中医 LoRA`；
   - 格内状态徽标：`inference_mode`（真实推理 vs 降级模拟）、`rag_status`（retrieved/empty/disabled）、命中条数；
   - 负向列额外打红色警示 `⚠️ 对抗性模式`，并在格内标出命中文档的 `risk_level` / `adversarial_strength` / `intent_tag`（证明注入确实发生了）。
4. **格内容**：模型回答正文（截断 + 可展开）+ 一行徽标。
5. **下方一个可折叠的 RAG 证据区**：按列列出 top-k 命中文档 + 实际拼好的完整 prompt；"无 RAG"列显示"未检索"。

> 为什么不做按钮：6 格本来就不多，平铺一眼看全更直观，也省掉"切换后重新渲染"的状态管理。
> 我方的管理面板已按此思路改成平铺 2×3，可对照参考（`rag_console/static/`）。

3. `opposed`（负向）是 RAG 侧的对抗性数据，仅实验用；若 Jette 侧的 RAG 返回 403，是
   `TCM_RAG_ALLOW_OPPOSED` 没开（Jette 已开）。
