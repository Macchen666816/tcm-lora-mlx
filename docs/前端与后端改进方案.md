# 前端与后端改进方案（暂不实施，仅设计说明）

> 依据分工：RAG 微服务（本机 Windows，含 MySQL + FAISS + 嵌入模型）已交付并在本仓库
> `rag_service/` 下可用；LoRA 训练与推理（同伴 MacBook）保持原有链路不变。
> 本文档描述**下一步**对 `webapp/`（前端 + 后端）的改造设计，**当前未改动任何 webapp 代码**。

---

## 1. 架构定位（共识确认）

RAG 微服务插入在链路的哪一环：

```
用户 query ──> [RAG 微服务] 检索+增强 ──> LoRA 推理（同伴 MacBook）──> 返回
                ▲                                  ▲
        MySQL 存向量化前的文档              原有链路完全不变
        FAISS 存向量化后的向量
```

- RAG 与 LoRA 微调是**链式线性、先后互不干扰**的关系：LoRA 解决"像不像中医专家"（风格、术语），
  RAG 解决"知识准不准"（事实、出处）；
- 我们只在 query→LLM 之间**插入一次** `/prepare`（或 `/generate`）调用，后续链路不破坏；
- 向量、MySQL 全部封装在 RAG 微服务内部，webapp 只面对一个 HTTP 接口。

## 2. webapp 后端改造点（`webapp/server.py`）

改动量：约 +60 行。原有 `/api/generate` 逻辑不动，新增前置于其上的 RAG 步骤。

### 2.1 新增配置

```python
RAG_URL = os.getenv("TCM_RAG_URL", "http://192.168.108.82:8090")  # Jette 的 Windows 机器
RAG_TIMEOUT = 5.0
```

启动时探测一次 `GET {RAG_URL}/health`，结果记入全局 `RAG_AVAILABLE`。

### 2.2 `/api/generate` 改造（伪代码）

```python
# 原逻辑：messages = [system, user(question)]
# 新逻辑：先用 RAG 增强问题；RAG 不可达则原样透传（降级，不报错）
rag_payload = None
if RAG_AVAILABLE:
    try:
        rag_payload = post(f"{RAG_URL}/prepare", json={
            "query": question, "top_k": 3, "enabled": True
        }, timeout=RAG_TIMEOUT)
        final_question = rag_payload["augmented_prompt"]
    except Exception:
        RAG_AVAILABLE = False          # 本轮降级，后续请求直接跳过
        final_question = question
else:
    final_question = question

response = RUNTIME.generate(variant, final_question, max_tokens)  # 原有调用不变
return {**response, "rag": rag_payload}   # 把 RAG 元数据带给前端
```

关键原则：
1. **RAG 挂了不影响回答**——降级为原始问题直答，前端标注"RAG 不可用"；
2. 增强提示词替代 `question` 传给模型，**system prompt 保持不变**；
3. 可选：把 LoRA 真实输出回写 `POST {RAG_URL}/traces/{trace_id}/outputs`，形成完整证据链
   （MySQL `query_traces` → `rag_retrievals` → `model_outputs` 三表串联）。

### 2.3 可选：新增 `/api/rag/preview`

只做检索不做推理，给前端"RAG 后提示词可视化"面板提供独立数据源
（调试检索质量时不用烧一次推理）。

## 3. webapp 前端改造点（`webapp/static/index.html` + `app.js`）

### 3.1 新增"RAG 检索详情"折叠面板（核心需求：RAG 后提示词可视化）

在每次回答卡片下方（或页面上方独立一栏）增加可折叠面板，展示三层信息：

| 区块 | 内容 | 数据来源 |
|---|---|---|
| ① 检索命中列表 | Top-k 文档标题、相似度分数、来源、命中摘要 | `rag.results[]` |
| ② **增强后提示词** | 完整 `augmented_prompt` 文本（等宽字体、可复制） | `rag.augmented_prompt` |
| ③ 链路元信息 | trace_id、rag_status、检索耗时 ms、数据库/索引后端 | `rag.*` |

视觉上建议用与"基座/LoRA 并排对比"同级的第三种主题色（如靛蓝），
并加一个醒目的状态徽标：

- `retrieved` → 绿色徽标"RAG 已增强"
- `empty` → 灰色徽标"未命中资料"
- `disabled` / RAG 不可达 → 黄色徽标"RAG 已降级（直答）"

### 3.2 交互细节

- 面板默认折叠，点击展开（答辩演示时点开讲链路，讲完收起）；
- 增强提示词区支持"复制"按钮，方便贴进报告截图；
- trace_id 做成可点击链接，跳 MySQL 查询说明（或直接展示 `/traces/{id}` 的 JSON）。

### 3.3 答辩叙事价值

前端可视化后，可现场演示同一个问题的三态对比：
1. 关闭 RAG：纯 LoRA 回答；
2. 开启 RAG：增强提示词（面板可见）+ LoRA 回答；
3. RAG 服务断开：自动降级直答 + 黄色徽标——直观展示"链路健壮性"。

## 4. 局域网联调方案（答辩用同伴电脑展示）

| 机器 | 角色 | 服务 |
|---|---|---|
| 同伴 MacBook | LoRA 训练机 + 答辩演示机 | `webapp/server.py`（端口 8088，`--host 0.0.0.0`） |
| Jette 的 Windows | RAG 微服务 + MySQL | `rag_service/server.py`（端口 8090，默认 `0.0.0.0`） |

连接方向：**MacBook → Windows**（只需同伴能访问我）。

### 4.1 Windows 侧（我）

```bash
# conda activate lora；服务默认监听 0.0.0.0:8090
cd G:/lora/tcm-lora-mlx
python -m rag_service.server
# 查本机局域网 IP（排除 VMware 虚拟网卡后为 192.168.108.82）
```

防火墙放行（管理员 PowerShell，一次性）：
```powershell
New-NetFirewallRule -DisplayName "TCM RAG 8090" -Direction Inbound -LocalPort 8090 -Protocol TCP -Action Allow
```

### 4.2 MacBook 侧（同伴）

```bash
# 启动原有 webapp（不动逻辑，改造后自动带 RAG）
.venv-mlx/bin/python webapp/server.py --host 0.0.0.0 --port 8088

# 环境变量指向我的 RAG 服务
export TCM_RAG_URL="http://192.168.108.82:8090"

# 【测试链路专用】不改造 webapp 时的替代方案：本机 curl 直测
curl http://192.168.108.82:8090/generate -H "Content-Type: application/json" \
  -d '{"query":"薄荷的性味归经和主要功效是什么？","top_k":3}'
```

`/generate` 的 `llm` 字段会显示 `inference_mode: remote-webapp / degraded-mock`，
同伴可据此判断链条是否通到了他的 LoRA。

### 4.3 防坑清单

- MacBook 访问 Windows 用**我的真实网卡 IP**（192.168.108.82），不要用 192.168.247.x /
  192.168.91.x（那是 VMware 虚拟网段，跨机不通）；
- 两台机器需在同一 Wi‑Fi / 热点；教室网络若开了 AP 隔离，用手机开热点让两台机器都连它；
- MySQL 只监听本机使用（RAG 服务在本机访问它），**不需要**对局域网暴露 3306，更安全；
- 答辩前跑一次 `health` 检查清单：`curl http://192.168.108.82:8090/health`，
  确认 `database=connected`、`embedder_backend` 含 `sentence-transformers`、`index_backend=faiss`。

## 5. 降级兜底策略总览（三层）

| 层 | 故障 | 兜底行为 | 对外标记 |
|---|---|---|---|
| 数据层 | MySQL 断连 | 知识文档改用内存种子数据 | `database: fallback-memory` |
| 嵌入层 | 模型加载失败 | 哈希 n-gram 嵌入 | `embedder_backend: hashing-fallback` |
| LLM 层 | 同伴 LoRA 不可达 | 本地基于检索资料合成模拟回答 | `degraded: true, inference_mode: degraded-mock` |

每一层降级都**如实标注、绝不静默**——答辩时这本身就是"链路健壮性设计"的加分叙事。
