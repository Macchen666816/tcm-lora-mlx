# 中医问答模型数据清洗工作答辩报告

## 一、工作目标

本项目的原始数据不是专门为本次中医问答模型准备的纯净数据，而是包含多种任务类型的混合问答数据。因此，数据清洗的目标不是单纯追求“数据越多越好”，而是得到一份：

1. 任务范围明确，主要服务于中医知识问答；
2. 格式统一，可以直接用于 MLX-LM 训练；
3. 训练集、验证集和测试集相互隔离，避免数据泄漏；
4. 对医疗建议、毒性药材、剂量和特殊人群等高风险样本进行单独处理；
5. 每一条样本都可以追溯到原始文件和原始行号。

需要特别说明的是：本项目做的是“规则清洗后的训练候选集”，不是经过中医专家逐条审核的医学知识库。自动规则能够识别格式问题、任务混杂、重复和显式风险，但不能证明某个药材功效或方剂配伍在医学上一定正确。

## 二、原始数据概况

原始数据由两个 JSONL 文件组成：

| 文件 | 记录数 | 用途 |
|---|---:|---|
| `data/chinese_medical_train.jsonl` | 5628 | 后续划分训练集和验证集 |
| `data/chinese_medical_test.jsonl` | 1408 | 只用于最终测试 |
| 合计 | 7036 | 清洗前总量 |

原始数据虽然整体与中医相关，但任务类型并不完全一致，包括知识问答、标题生成、长文写作、改写、抽取分类等。如果把这些内容不加区分地放进训练集，模型可能学到错误的任务边界，例如用户问一个药材功效，模型却输出论文标题。

## 三、清洗流程

本次清洗由两个主要脚本完成：

- `scripts/audit_dataset.py`：对每条原始记录做结构检查、任务分类和风险标记；
- `scripts/prepare_training_data.py`：依据审计结果完成筛选、去重、划分、格式转换和追溯文件生成。

整体流程如下：

```text
原始 JSONL
    ↓
读取与结构检查
    ↓
文本规范化、任务分类、风险标记
    ↓
移出非知识问答和硬错误样本
    ↓
去重与训练/测试泄漏检查
    ↓
按主题确定性划分 train / valid
    ↓
生成 MLX 格式、Alpaca 格式和追溯文件
    ↓
结构、数量、哈希和集合隔离验证
```

### 1. 读取和字段检查

首先逐行读取 JSONL，并给每条数据记录原始行号。每条样本要求包含 `instruction`、`input` 和 `output` 三个字段，且字段值必须是非空字符串。

同时对文本做轻量规范化：压缩连续空白、去除首尾空格，但不擅自改写原始答案内容。这样做可以统一格式，也方便后续去重；原始数据文件本身保持不变。

### 2. 任务分类

根据问题文本中的稳定关键词，把样本划分为以下几类：

- `knowledge_qa`：中医知识问答，作为本项目主要目标；
- `title_generation`：根据内容生成文章标题；
- `long_form_generation`：要求撰写研究文献、摘要或长文；
- `rewriting_editing`：改写、润色或编辑；
- `extraction_classification`：抽取、分类或归类。

最终训练范围只保留 `knowledge_qa`。这不是说其他任务本身没有价值，而是为了让本次模型的任务目标单一、评测结果可解释。

### 3. 结构质量和明显错配检查

审计脚本对每条记录增加审计标记，而不是一发现问题就直接删除。主要检查包括：

- 缺少字段、字段不是字符串、问题或答案为空；
- 占位符答案；
- 极短答案；
- 只有标题或只有小标题的答案；
- 问题要求知识回答，但答案却是论文标题或文档标题；
- 指令格式明显损坏；
- 中英文片段异常混杂。

其中，“答案短”只是风险标记，不是单独的删除条件。因为“白术有什么功效”这类问题本来可能只需要简短回答，不能仅凭字数判定为坏数据。只有标题错配、占位内容、格式损坏等证据比较明确时，才作为硬排除条件。

### 4. 医疗安全规则

中医数据有一个普通文本数据没有的特点：答案可能涉及个人诊断、处方、剂量、毒性药材、孕妇儿童或急重症。因此增加了安全规则，重点识别：

- 个人症状和个体化用药建议；
- 剂量或服用量问题；
- 严重疾病或急症；
- 孕妇、儿童、老人等特殊人群；
- 附子、草乌等潜在毒性药材；
- 直接声称“保证有效”“彻底治愈”等绝对化表述；
- 要求现代药理、疗效或研究结论，但答案没有可核查来源的研究声明。

如果问题属于上述高风险类型，而且答案缺少“应就医”“遵医嘱”“由专业人员辨证”等安全约束，就进入排除或隔离范围。安全样本没有被物理删除，而是保存到 `data_processed/safety_quarantine.jsonl`，便于后续做安全对齐训练或人工复核。

### 5. 去重

清洗脚本在规范化文本后，分别检查：

- 问题是否重复；
- 问题与答案组合是否重复；
- 答案是否重复。

重复样本只保留首次出现的记录，其他记录写入 `excluded.jsonl` 并注明排除原因。这样可以减少某一条模板答案被重复学习造成的偏置。

### 6. 防止数据泄漏

原始测试集始终不参与训练和验证。训练数据先按主题分组，再用固定哈希顺序进行 9:1 的验证集划分，因此每次复现都会得到相同结果。

划分完成后，又对 train、valid、test 三个集合做规范化问题交集检查，并检查答案是否与训练/验证集合重复。如果测试问题或答案已经出现在训练/验证数据中，就从测试集移出并记录为 `leakage`。

这一步很重要，因为如果测试题和训练题重复，模型得到的高分可能只是记忆，而不能说明泛化能力。

### 7. 生成训练格式和追溯信息

最终同时生成两种格式：

- `data_processed/mlx/*.jsonl`：每条样本是 `system / user / assistant` 三轮消息，直接供 MLX-LM 使用；
- `data_processed/alpaca/*.jsonl`：保留 `instruction / input / output` 三字段，方便迁移到其他训练框架。

此外还生成：

- `lineage.jsonl`：记录最终样本对应的原始划分、原始行号、主题和审计标记；
- `excluded.jsonl`：记录所有未入选样本及明确排除原因；
- `manifest.json`：记录数量、规则版本和 SHA-256；
- `medical_spotcheck.csv`：按集合和主题抽取的分层抽检表；
- `evaluation/core_benchmark.jsonl`：从测试集固定抽取的核心评测题，绝不进入训练。

## 四、清洗结果

最终结果如下：

| 数据集 | 数量 | 说明 |
|---|---:|---|
| train | 3061 | 来自原始训练集，约 90% |
| valid | 341 | 来自原始训练集，约 10% |
| test | 850 | 来自原始测试集，仅用于评测 |
| 最终保留合计 | 4252 | 可用于训练或评测 |
| 排除合计 | 2784 | 均保留排除原因和原始追溯信息 |

主要排除原因包括：

| 原因 | 数量 |
|---|---:|
| 非目标任务：标题生成 | 555 |
| 非目标任务：抽取分类 | 551 |
| 非目标任务：长文生成 | 480 |
| 非目标任务：改写编辑 | 125 |
| 缺少可核查来源的研究声明 | 976 |
| 个人建议但缺少安全提示 | 385 |
| 特殊人群但缺少安全提示 | 85 |
| 有毒药材但缺少安全提示 | 89 |
| 其他格式、标题错配、重复和泄漏 | 其余 |

安全隔离集共 663 条，研究声明隔离集共 976 条。这里的“隔离”比“删除”更准确，因为这些样本仍然保存在项目中，后续可以由专业人员审核或用于专门的安全训练。

## 五、质量验证

清洗完成后没有只看文件能否打开，而是运行了独立验收脚本 `scripts/validate_processed_data.py`，验证内容包括：

1. JSONL 每行都能解析，且没有空行；
2. Alpaca 和 MLX 两种格式字段正确、数量一致、内容一致；
3. train、valid、test 的问题没有规范化重复；
4. 三个集合使用同一份系统提示；
5. `lineage` 数量与最终保留样本数量一致，且 ID 不重复；
6. 最终保留数加排除数等于原始总数 7036；
7. 原始文件和输出文件 SHA-256 校验通过；
8. 54 道核心基准题全部来自 test，未混入训练；
9. 24 道安全对抗题字段完整且 ID 不重复。

本次验收结果为：

```text
test: 850
excluded: 2784

```

## 六、我在答辩中应该如何表述这项工作

### 90 秒口述版

> 本项目原始数据共有 7036 条，包含训练集 5628 条和测试集 1408 条。清洗时我没有直接按字数粗暴删除，而是先使用脚本逐条读取数据，检查字段、空值和 JSON 格式，并根据问题内容区分知识问答、标题生成、长文写作、改写和抽取分类等任务。因为本项目目标是中医知识问答，所以训练范围只保留 knowledge QA。
>
> 接着，我对标题错配、占位答案、格式损坏、重复和中英文异常片段进行标记；对个人用药、剂量、毒性药材、特殊人群和严重疾病等内容增加安全规则。如果缺少就医或遵医嘱提示，就将样本排除或放入安全隔离集，而不是直接丢弃。之后对问题和答案做规范化去重，并按照主题固定划分训练集和验证集，同时检查测试集与训练集是否有问题或答案重叠，防止数据泄漏。
>
> 最终得到 3061 条训练数据、341 条验证数据和 850 条测试数据，共保留 4252 条。所有被排除的数据仍然保存在 excluded 文件中，并记录排除原因；保留数据则通过 lineage 文件追溯到原始行号。最后再用独立验证脚本检查格式、数量、集合隔离和 SHA-256 校验。需要说明的是，这套流程解决的是数据结构、任务边界和显式安全风险，并不能替代中医专家对每条医学事实的审核。

### 老师可能追问：为什么不全部人工检查？

可以回答：

> 原始数据有 7036 条，逐条人工审核成本很高，而且本项目重点是展示可复现的数据工程流程。因此先用确定性规则完成全量审计和风险分层，再生成分层抽检表，把人工精力集中到医疗建议、毒性药材、特殊人群和研究声明等高风险样本。自动规则提高了效率，但我没有把它包装成医学事实审核。

### 老师可能追问：为什么保留 `excluded.jsonl`，不直接删除？

可以回答：

> 因为排除不等于数据一定错误。例如研究声明样本可能有价值，只是当前没有可靠来源；安全样本也可以用于后续安全对齐。保留排除记录和原因可以审计、复现和二次利用，同时避免误删后无法解释。

### 老师可能追问：如何证明没有数据泄漏？

可以回答：

> 测试集从来源上就没有参与训练和验证；训练集内部按主题固定划分 train 和 valid；划分后又对三个集合的问题做规范化集合交集检查，并检查测试题答案是否与训练/验证重复。最终验收结果是跨集合问题重叠为 0。

### 老师可能追问：自动规则会不会误删？

可以回答：

> 会存在误判可能，所以规则分成硬排除、风险标记和隔离三类。短回答本身不会自动删除；无法判断医学事实的内容不直接改写；所有排除记录带有原因和来源信息。后续如果有中医专业人员参与，可以根据 `medical_spotcheck.csv` 和 `excluded.jsonl` 进行复核和回收。

## 七、局限和后续改进

当前清洗仍有三个限制：

1. 关键词规则无法可靠判断药材功效、归经、方剂配伍和现代研究结论是否正确；
2. 数据中仍可能存在未被规则发现的医学事实错误；
3. 当前抽检表已经生成，但尚未完成中医专业人员逐条签字审核。

因此后续可以增加：

- 中医专业人员对高风险抽样数据进行双人复核；
- 建立药材、方剂和禁忌的可靠知识源交叉验证；
- 将“事实正确性”“安全性”“任务完成度”分别作为评测维度；
- 根据人工复核结果迭代规则，而不是只增加关键词数量。
