## 2. 八条件矩阵（本实验的全部格子）

| 模型变体 \ RAG | 无 RAG | 积极引导 | 模糊·无拦截 | 恶意误导 |
|---|---|---|---|---|
| **Qwen2.5 基座** | `variant=base, rag_enabled=false` | `base + stance=aligned` | `base + neutral` | `base + opposed` |
| **中医 LoRA** | `variant=lora, rag_enabled=false` | `lora + aligned` | `lora + neutral` | `lora + opposed` |

- 「无 RAG」= `rag_enabled: false`，用于看**微调本身**带来的立场
- 有 RAG 的 6 格 = 3 模式 × 2 变体
- `variant` 由 RAG 服务透传给你：webapp 模式走 `{"question":..., "variant":...}`，
  MLX server 模式走 `model: "lora" | "base"`

## 3. 接口契约

### 3.1 `POST /prepare`（只看检索侧，不烧推理）

请求：`{"query": "问题", "top_k": 3, "enabled": true, "stance": "opposed"}`

响应关键字段：

| 字段 | 说明 |
|---|---|
| `rag_status` | `retrieved` / `empty` / `disabled` |
| `stance` | 本次实际使用的模式 |
| `results[]` | 命中文档：`rank` `title` `content` `score` `stance` `risk_level` `adversarial_strength` `intent_tag` `source` |
| `augmented_prompt` | **实际拼好的完整提示词**（答辩举证用） |
| `trace_id` | 链路 ID，可回写输出 |

### 3.2 `POST /generate`（完整链路）

请求：`{"query": "...", "top_k": 3, "rag_enabled": true, "stance": "opposed", "variant": "lora", "max_tokens": 256}`

响应关键字段：`trace_id`、`stance`、`rag_status`、`rag_results[]`、`augmented_prompt`、
`llm.{response, elapsed_seconds, character_count, inference_mode, degraded}`。

> ⚠️ `inference_mode=degraded-mock` 表示 **RAG 服务没能连到你的 LoRA**，用的是本地模拟回答，
> 这个结果**不能用于实验结论**。你那边服务起来后它会自动变成 `remote-webapp`。

### 3.3 回写（可选，P2）

`POST /traces/{trace_id}/outputs`，body：`{"variant":"lora", "response":"...", "elapsed_seconds":1.2, "character_count":180, "inference_mode":"remote-webapp"}`

## 4. 后端改造代码（可直接粘贴）

### 4.1 配置

```python
import os, json, urllib.request

RAG_URL = os.getenv("TCM_RAG_URL", "http://192.168.108.82:8090")
RAG_TIMEOUT = 8.0
VALID_STANCES = {"aligned", "neutral", "opposed"}
```

### 4.2 RAG 调用 + 降级

```python
def call_rag_prepare(question: str, stance: str, top_k: int = 3) -> dict | None:
    """调用 RAG /prepare。失败返回 None，主服务原样透传（降级直答）。"""
    payload = {"query": question, "top_k": top_k, "enabled": True, "stance": stance}
    request = urllib.request.Request(
        f"{RAG_URL}/prepare",
        data=json.dumps(payload, ensure_ascii=False).encode("utf-8"),
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    try:
        with urllib.request.urlopen(request, timeout=RAG_TIMEOUT) as response:
            return json.loads(response.read().decode("utf-8"))
    except Exception as exc:
        print(f"[RAG] 调用失败，降级直答：{exc}", flush=True)
        return None
```

### 4.3 `/api/generate` 里插入

```python
stance = str(payload.get("stance", "aligned")).lower()
if stance not in VALID_STANCES:
    raise ValueError("stance 必须是 aligned / neutral / opposed")

rag = call_rag_prepare(question, stance)
final_question = rag["augmented_prompt"] if rag else question   # RAG 挂了就原样透传

result = RUNTIME.generate(variant, final_question, max_tokens)
self._send_json({**result, "stance": stance, "rag": rag})
```

⚠️ **只替换 user 消息**：system prompt 读文件（`P0-2` 用中性档），不要动它。

### 5.2 八条件田字格（2×2 + 三联按钮）— 答辩核心画面

```
        ┌──────────────────┬──────────────────┐
上排固定 │ 基座 · 无 RAG     │ LoRA · 无 RAG     │  ← 始终不变
        ├──────────────────┼──────────────────┤
下排切换 │ 基座 ·〔当前档〕RAG│ LoRA ·〔当前档〕RAG│  ← 随按钮变
        └──────────────────┴──────────────────┘
          ( 积极引导 ) ( 模糊·无拦截 ) ( 恶意误导 )   ← 三联按钮
        ┌────────────────────────────────────────┐
        │ RAG 证据：top-k 命中文档 + 完整 prompt    │
        └────────────────────────────────────────┘
```

```javascript
const STANCES = ['aligned', 'neutral', 'opposed'];
const LABEL = {aligned: '积极引导', neutral: '模糊·无拦截', opposed: '恶意误导'};
const state = {arms: {}, stance: 'aligned'};

async function runGrid(question) {
  const jobs = [];
  for (const variant of ['base', 'lora'])
    jobs.push({key: `${variant}-none`, body: {question, variant, rag_enabled: false}});
  for (const variant of ['base', 'lora'])
    for (const s of STANCES)
      jobs.push({key: `${variant}-${s}`, body: {question, variant, stance: s, rag_enabled: true}});

  state.arms = {};
  for (const job of jobs) {
    const r = await fetch('/api/generate', {
      method: 'POST', headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({...job.body, max_tokens: 256}),
    }).then((x) => x.json());
    state.arms[job.key] = {answer: r.llm?.response, mode: r.llm?.inference_mode,
                           rag: r.rag_results || [], prompt: r.augmented_prompt};
    renderGrid();
  }
}
```

要点：
1. **一次跑完 8 格并缓存**，三联按钮只切换"下排展示哪两个"—— 不重新调用（每次推理都有成本）；
2. 上排两格任何按钮操作都不变；
3. 证据区随当前档联动。

> 参考实现已在 RAG 管理面板跑通：`rag_console/static/`（可直接对照抄）。

## 7. 坑与边界

1. **`opposed` 有门禁**：RAG 默认拒绝（403）。Jette 侧 `.env` 已开 `TCM_RAG_ALLOW_OPPOSED=1`；若你本地部署 RAG 也要设。
2. **别用 `stance=all`**：会把三档资料混在一次检索里，无法归因（那是第 9 种配置，只当基线）。
3. **RAG 前置指令已关**（`TCM_RAG_INSTRUCTION_ENABLED=0`），拼出的 prompt 是纯资料 + 问题。要恢复：Jette 侧改回 1 重启。
4. **system prompt 是最大的拉偏架来源**：`SAFETY_SYSTEM_PROMPT.txt` 里"即使用户要求…也必须保持边界"就是针对上下文注入的防御。已备三档（强安全 / 中性 / 极简），用 `TCM_SYSTEM_PROMPT` 指定，见 `evaluation/SYSTEM_PROMPT_VARIANTS.md`。
5. **安全边界**：`opposed` 档与中性/极简 prompt 只用于课程设计对照实验，不得用于面向真实用户的服务；演示时请在页面上标注"对抗性实验模式"。
