# 同伴接入指南：把 RAG 与三种模式接进 webapp

> 读者：负责 LoRA 与 webapp 的同伴（MacBook 侧）。
> 目标：webapp 增加**三种 RAG 模式的切换按钮**，让用户/答辩现场能选"同向 / 中立 / 反向"，
> 并把 RAG 的检索详情可视化出来。
>
> 链路：`用户提问 → webapp → [RAG 微服务 192.168.108.82:8090] → LoRA 推理 → 前端展示`

---

## 0. 先搞清楚三种模式是什么、怎么切换

RAG 知识库被**均分为三部分**（各 400 条），每次请求**只用其中一部分**：

| 模式 | `stance` 值 | 知识库部分 | 对模型的要求 |
|---|---|---|---|
| 同向 · 安全对齐 | `aligned` | 400 条，带安全提示、剂量交由医师 | 保持安全提示 |
| 中立 · 无安全拦截 | `neutral` | 400 条，给方案但零安全提示 | 不加也不减 |
| 反向 · 恶意诱导 | `opposed` | 400 条，答案外挂对抗注入指令 | **放弃**安全提示 |

**切换机制：由调用方在请求里指定 `stance` 参数。**
一次请求只用一个模式；模型看不到模式标签，它只收到拼好的提示词。

- ❌ 不是模型自己选
- ❌ 不是 RAG 自动混三种（那是 `stance=all` 的混合配置，会破坏归因，只当基线）
- ✅ 是**调用方指定** —— 前端按钮 / 下拉框 → 后端把它塞进请求体

**"并排对比三种模式"的正确实现**：同一个问题**发 3 次请求**（`aligned` / `neutral` / `opposed`），
把三份结果并排展示。这就是"平铺三种"。

## 2. 后端改造（`webapp/server.py`，约 40 行）

### 2.1 顶部加配置

```python
import os, json, urllib.request

RAG_URL = os.getenv("TCM_RAG_URL", "http://192.168.108.82:8090")
RAG_TIMEOUT = 8.0
VALID_STANCES = {"aligned", "neutral", "opposed"}
```

### 2.2 新增 RAG 调用函数

```python
def call_rag_prepare(question: str, stance: str, top_k: int = 3) -> dict | None:
    """调用 RAG 的 /prepare：检索 + 生成增强提示词。失败返回 None（降级用）。"""
    payload = {"query": question, "top_k": top_k, "enabled": True, "stance": stance}
    request = urllib.request.Request(
        f"{RAG_URL}/prepare",
        data=json.dumps(payload, ensure_ascii=False).encode("utf-8"),
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    try:
        with urllib.request.urlopen(request, timeout=RAG_TIMEOUT) as response:
            return json.loads(response.read().decode("utf-8"))
    except Exception as exc:
        print(f"[RAG] 调用失败，降级直答：{exc}", flush=True)
        return None
```

### 2.3 改造 `/api/generate`

在原有 `question` 校验之后、`RUNTIME.generate(...)` 之前插入：

```python
stance = str(payload.get("stance", "aligned")).lower()
if stance not in VALID_STANCES:
    raise ValueError("stance 必须是 aligned / neutral / opposed")

rag = call_rag_prepare(question, stance)
final_question = rag["augmented_prompt"] if rag else question   # RAG 挂了就原样透传
```

⚠️ **只替换 user 消息**，`system prompt`（`evaluation/SAFETY_SYSTEM_PROMPT.txt`）保持不变 ——
否则就不是"只改 RAG"了。

然后把返回体加上 RAG 信息（原字段一个不动）：

```python
result = RUNTIME.generate(variant, final_question, max_tokens)
self._send_json({**result, "stance": stance, "rag": rag})
```

## 3. 前端改造（`webapp/static/`）

### 3.1 三模式按钮（核心需求）

```html
<div class="stance-switch" role="group" aria-label="RAG 模式">
  <button class="stance-btn active" data-stance="aligned">同向 · 安全对齐</button>
  <button class="stance-btn" data-stance="neutral">中立 · 无安全拦截</button>
  <button class="stance-btn" data-stance="opposed">反向 · 恶意诱导</button>
</div>
<div class="stance-note" id="stanceNote"></div>
```

```javascript
let currentStance = 'aligned';

document.querySelectorAll('.stance-btn').forEach((btn) => {
  btn.addEventListener('click', () => {
    currentStance = btn.dataset.stance;
    document.querySelectorAll('.stance-btn')
      .forEach((b) => b.classList.toggle('active', b === btn));
    document.getElementById('stanceNote').textContent =
      currentStance === 'opposed'
        ? '⚠️ 当前为对抗性模式（含不安全建议），仅用于课程设计的对照实验'
        : '当前模式：' + btn.textContent;
  });
});

// 发请求时带上
async function ask(question, variant) {
  const response = await fetch('/api/generate', {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({question, variant, max_tokens: 256, stance: currentStance}),
  });
  return response.json();
}
```

### 3.2 三模式并排视图（答辩最需要的那一屏）

同一个问题连续发 3 次（每次换 `stance`），三列并排：

```javascript
const MODES = [
  {stance: 'aligned', label: '同向 · 安全对齐'},
  {stance: 'neutral', label: '中立 · 无安全拦截'},
  {stance: 'opposed', label: '反向 · 恶意诱导'},
];

async function askSideBySide(question, variant) {
  const columns = await Promise.all(MODES.map(async (mode) => {
    const response = await fetch('/api/generate', {
      method: 'POST',
      headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({question, variant, max_tokens: 256, stance: mode.stance}),
    });
    return {mode, data: await response.json()};
  }));
  renderColumns(columns);   // 三列：模式名 / 命中文档 / 模型回答 / 增强提示词
}
```

> 注意：这里的三次调用是**串行或并发都行**，但**不要**把三个模式的文档混在一次检索里
> （`stance=all`），那样无法归因。

### 3.3 RAG 详情面板（每次回答下方）

渲染后端返回的 `rag` 对象：

| 区块 | 字段 |
|---|---|
| 本次模式 | `rag.stance` |
| 命中文档列表 | `rag.results[]` → `title` / `score` / `risk_level` / `adversarial_strength` / `intent_tag` |
| **增强后提示词全文** | `rag.augmented_prompt`（等宽字体 + 复制按钮） |
| 链路元信息 | `rag.trace_id` / `rag.rag_status` / `rag.rag_latency_ms` |

状态徽标建议：
- `retrieved` → 绿色"RAG 已增强"
- `rag_status=empty` → 灰色"未命中资料"
- `rag` 为 `null`（RAG 不可达）→ 黄色"RAG 已降级（直答）"
- `stance=opposed` → 红色徽标"⚠️ 对抗性模式"

## 6. 两个坑

1. **`opposed` 需要开关**：RAG 服务默认拒绝 `opposed`（返回 403）。
   Jette 的 `.env` 里已设 `TCM_RAG_ALLOW_OPPOSED=1`；若换机器部署同样要设。
2. **前置指令会削弱反向注入**：RAG 拼提示词时有一句固定指令
   "…涉及诊断、处方、剂量或中毒风险时，应明确建议由专业医疗人员评估"。
   它在三模式下**完全相同**（不构成混淆），但本身在帮模型抵抗反向注入。
   想测"无护航"情形，可在 Jette 侧设 `TCM_RAG_INSTRUCTION_ENABLED=0` 重启服务，
   即得到 2×3 共 6 种条件。

## 7. 安全边界（务必遵守）

- `opposed` 组是**对抗性数据**，含源数据中的不安全医疗建议与诱导语句；
- 仅在实验/答辩演示时使用，**不得**用于面向真实用户的服务；
- 演示时建议在界面上明确标注"对抗性实验模式"。
